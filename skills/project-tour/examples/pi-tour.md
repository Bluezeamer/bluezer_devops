## 一、这是什么

一个住在终端里的编程助手。你用日常语言告诉它要做什么——"帮我把这个函数改成支持批量处理"——它会真的去打开你的文件、读懂、修改、必要时执行命令，然后告诉你做完了。

它和"聊天式 AI"的区别在于：AI 只会给你一段建议让你自己贴回去，而它**真的动手**。

## 二、拓扑结构

```
    你 ──说话──►┌────────────────┐
                │    产品外壳     │  把下面这些组装成一个能用的程序
    你 ◄─看到───└───────┬────────┘  管：怎么启动、怎么配置、记录存哪
                        │ 取用
       ┌────────────────┼──────────────┬─────────────┐
       ▼                ▼              ▼             ▼
  ┌─────────┐     ┌──────────┐   ┌─────────┐  ┌──────────┐
  │ 执行引擎 │────►│ 模型接口  │   │ 画面绘制 │  │ 远程通道 │
  │         │     │          │   │         │  │          │
  │ 自带动手 │     │ 统一各家  │   │ 在终端里 │  │ 让助手能 │
  │ 能力：读 │     │ AI 的差异 │   │ 画出界面 │  │ 跑在别的 │
  │ 写/改文件│     │          │   │         │  │ 机器上   │
  │ /执行命令│     └─────┬────┘   └─────────┘  └──────────┘
  └─────────┘           │
                        ▼
                 ┌─────────────┐
                 │ 外部 AI 服务 │  真正"思考"的地方，在别人家的服务器上
                 └─────────────┘
```

**形状**：一个总装点（产品外壳），下面挂着四块**彼此不打交道**的能力。四块之间没有任何连线——这是这个结构最重要的特征。

另有两块辅助：运行记录（记下过程中发生了什么）、效果评测（衡量这个助手干得好不好）。还有一块与谁都无往来，作用尚未确认。

## 三、各部分如何交互

**先看一次完整的过程**——你说一句"帮我给这个函数加上错误处理"之后发生的事：

1. **产品外壳**收下你的话，交给**执行引擎**。
2. **执行引擎**不会自己思考，它通过**模型接口**去问外面的 AI：用户想做这件事，下一步该干什么？
3. AI 回答：*"我需要先看看那个文件。"*
4. **执行引擎**真的去把文件读出来，再把内容送回给 AI。
5. AI 看过后说：*"把第 30 到 40 行换成这样。"*
6. **执行引擎**真的去改这个文件。
7. 改完的结果再送回 AI，AI 判断：还没完，接着说下一步；或者：做完了。
8. 这个"问 → 做 → 回报 → 再问"的圈会一直转，直到 AI 说结束。
9. 整个过程中，**画面绘制**把每一步实时显示给你看。

**这个循环就是整个项目的心脏。** 明白了它，其余都是围绕它的安排。

**为什么这样分是合理的**——

- **思考和动手是分开的。** AI 只负责判断"下一步该做什么"，它没有能力碰你的文件；执行引擎只负责动手，它自己不做任何判断。两者都不完整，合起来才成事。好处是：换一个更聪明的 AI，动手的部分完全不用改。

- **"各家 AI 的差异"被关在一个房间里。** 世界上有很多家 AI 服务，接口各不相同。模型接口这块的唯一职责就是把它们抹平成一个样子，让执行引擎眼里"只有一个 AI"。所以新增一家供应商，只需改这一块。

- **界面只是观众，不参与决策。** 画面绘制只接收"发生了什么"然后显示，从不反过来影响执行引擎做什么。所以把界面整个换掉，助手照样工作。

- **远程通道两端只靠一份约定连接。** 发话的一端和接话的一端不直接认识对方，双方只共同遵守一份"数据该怎么打包"的约定，因此可以各自独立改动。值得注意的是：接话那一端**并不包含执行引擎**——所以远程模式不是"把整个助手搬到服务器上"，而是另一种更轻的组合方式。

**一个容易想反的地方**：听名字会以为"动手的能力"（读文件、改文件、执行命令）是产品外壳提供的。实际相反——**这些能力长在执行引擎里**。产品外壳负责的是另一类事：怎么启动、支持哪几种使用方式、账号配置、记录存哪。执行引擎是自带手脚的，产品外壳只是给它穿上衣服。

## 四、术语对照表

| 导览中的说法 | 项目/领域中的正式名称 | 一句解释 |
|---|---|---|
| 产品外壳 | `coding-agent` 包 | 组装成品，管启动方式、配置与记录 |
| 执行引擎 | `agent` 包 | 驱动"问→做→回报"循环，自带读写文件与执行命令的能力 |
| 模型接口 | `ai` 包 | 把各家 AI 服务的接口差异抹平成同一套 |
| 画面绘制 | `tui` 包 | Terminal UI，终端里的文字界面 |
| 远程通道 | `protocol` / `client` / `server` 包 | 分别是：数据打包的约定、发话端、接话端 |
| 运行记录 | `telemetry` 包 | 遥测，记录运行中发生的事件与耗时 |
| 效果评测 | `evals` 包 | evaluation，衡量 agent 完成任务的质量 |
| 数据打包的约定 | CBOR | 一种紧凑的二进制数据格式，跨语言通用 |
| 只重画变化的部分 | 差分渲染 | 比较新旧画面，只更新不同处，避免闪烁 |
| 几种使用方式 | 交互模式 / 打印模式 / 远程调用模式 | 分别是：对话着用、执行一次就退出、被别的程序调用 |
| 作用尚未确认的那块 | `session-backends` 包 | 与其他部分无依赖往来，需展开确认 |
